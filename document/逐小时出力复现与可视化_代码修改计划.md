# 逐小时出力复现与可视化：统一代码修改计划

> 适用仓库：`npuNancy/globally-interconnected-solar-wind-system-addresses-future-electricity-demands`  
> 适用分支：`dev-SSPs`  
> 适用目录：`Optimization_ssp126/`、`Optimization_ssp245/`、`Optimization_ssp560/`

---

## 1. 目标与总体结论

当前 `Optimization_ssp*` 中的调度函数已经在每次目标函数评价时执行完整的 8760 小时调度，但函数结束时只返回三个汇总目标：

1. 弃电率；
2. 灵活电源比例；
3. 系统总成本。

逐小时发电、输电、储能、弃电和灵活电源数组均未写入结果文件。

本次修改采用以下方案：

> **不在 NSGA-II 优化过程中保存逐小时结果。**  
> 保留现有 Pareto 结果文件中的决策向量 `res_scale`，选出 preferred solution 后，仅对最终解重新执行一次确定性的 8760 小时调度，导出逐小时结果，再用 Python 绘图。

这种方式兼顾可复现性、磁盘开销和代码风险。第一阶段采用“新增文件为主”的低风险实现，不改变现有优化目标函数的行为；在功能验证完成后，再考虑将重复逻辑抽取为公共函数。

## 2. 当前代码基线

### 2.1 当前优化结果已经保留了复现所需的决策变量

以 `Optimization_ssp126/Optimization_SC_2050.m` 为例，优化结束后写入：

```text
results/Optimization_SC_2050_Res.h5
├── /res_scale   # 每个 Pareto 解的完整决策向量
└── /prs         # 每个 Pareto 解的三个目标函数值
```

单个 `scale` 决策向量的结构为：

```text
[
  光伏选址变量,
  风电选址变量,
  20 个区域的储能功率,
  20 个区域的储能时长,
  输电链路容量
]
```

因此，无需保存每个 Pareto 解的逐小时调度数组。只要保留 `res_scale`、输入数据和候选格网构建逻辑，就可以在优化完成后重放任意一个 Pareto 解。

### 2.2 当前调度函数已经计算但没有导出的数组

以 `Optimization_ssp126/OptFun_SC_Dispatch_2050.m` 为例，函数内部已经计算：

| 变量 | 维度 | 含义 |
|---|---:|---|
| `grid_gens` | `20 × 8760` | 各区域风光总出力 |
| `grid_load` | `20 × 8760` | 扣除基荷后的净负荷 |
| `stored_ele` | `8761 × 20` | 储能荷电状态 |
| `curtailed_ele` | `8760 × 20` | 弃电量 |
| `flexible_ele` | `8760 × 20` | 灵活电源补足量 |
| `shifted_ele` | `8760 × 20 × 20` | 区域间送出电量 |
| `consumed_ele` | `8760 × 20` | 本地直接消纳的风光电量 |

但函数最终只返回：

```matlab
f(1) = sum(curtailed_ele(:)) ./ sum(grid_gens(:));
f(2) = sum(flexible_ele(:)) ./ sum(loads(:));
f(3) = obj_cost;
```

### 2.3 当前仓库已有可参考的诊断型调度函数

`Resilience/Fun_SC_Dispatch_2040.m` 和 `Resilience/Fun_SG_Dispatch_2050.m` 已经使用多输出形式返回：

```matlab
[f, con, flex, curtail, storage, shifted]
```

这说明逐小时数组导出在结构上可行。但这些旧函数包含旧的硬编码基荷比例，不能直接用于 `dev-SSPs` 的结果复现。本次应复用其“输出结构思路”，不直接复用其参数逻辑。

## 3. 关键设计决策

### 3.1 不在优化阶段写逐小时结果

不建议在 `gamultiobj` 调用的 `OptFun_*_Dispatch_*.m` 中对每个评价个体写文件，原因包括：

- 优化过程会评价大量中间个体，其中绝大多数不会成为最终 Pareto 解；
- `UseParallel=true` 时多个 worker 同时写文件，容易产生文件竞争和严重 I/O 开销；
- `shifted_ele` 单个数组已经达到 `8760 × 20 × 20 = 3,504,000` 个数值；
- 保存所有评价个体会产生大量无效文件。

正确做法是：

```text
优化阶段：只保存 Pareto 解的 res_scale 和 prs
        ↓
筛选 preferred solution
        ↓
重放最终解一次
        ↓
保存逐小时详细结果
```

### 3.2 第一阶段不修改现有优化函数

第一阶段优先新增独立重放模块，不修改：

```text
OptFun_*_Dispatch_*.m
Optimization_*.m
nonlcon*.m
```

原因是这些文件直接决定 Pareto 前沿。先采用附加式实现，可以降低引入新 bug 后必须重新运行优化的风险。

### 3.3 第二阶段再考虑重构公共核心

独立重放模块与原目标函数会存在部分逻辑重复。第一阶段必须通过严格回归测试确保一致。功能稳定后，再考虑将调度循环抽取为公共核心函数，使优化与重放共用同一份逻辑。

## 4. 对初始方案的必要修正

### 4.1 不只区分“光伏”和“风电”

为了满足能源类型可视化，应精确拆分为：

```text
光伏
陆上风电
海上风电
基荷
灵活电源
```

光伏候选格网位于 `all_gens` 的前 `nonlsol` 行；风电位于后续行。风电还可以通过 `CGrid_Index(:, 3)` 的陆海标记区分为陆上风电和海上风电。

### 4.2 原始出力图与实际供电结构图必须分开

不能直接将以下变量堆叠后与负荷曲线比较：

```text
基荷 + 光伏原始出力 + 风电原始出力 + 储能放电 + 灵活电源
```

原因是：

- 光伏和风电原始出力中包含弃电；
- 原始出力中包含被送往其他区域的电量；
- 原始出力中包含储能充电电量；
- 储能放电来自此前已经计入的风光发电，再次堆叠会重复计算。

因此，绘图必须至少分成两类：

**图 A：发电侧原始出力**

```text
光伏原始出力
陆上风电原始出力
海上风电原始出力
+ 原始负荷折线
```

**图 B：负荷侧实际供电结构**

```text
基荷
本地直接消纳风光
跨区输入电量
储能放电
灵活电源
= 原始负荷
```

图 A 用于展示不同能源类型的波动特征；图 B 用于展示调度后如何满足负荷。

### 4.3 需要同时保存输电送出量、受入量和输电损耗

当前 `shifted_ele` 记录的是送端发出的电量。输电过程中存在损耗，因此还应新增：

```text
shifted_sent_ele
shifted_received_ele
transmission_loss_ele
```

其中：

```text
shifted_received_ele = shifted_sent_ele × (1 - route_loss)
transmission_loss_ele = shifted_sent_ele - shifted_received_ele
```

### 4.4 使用 MATLAB `-v7.3` 时，Python 端不能只依赖 `scipy.io.loadmat`

逐小时结果包含三维输电数组，建议 MATLAB 使用：

```matlab
save(outfile, ..., '-v7.3');
```

MATLAB v7.3 文件基于 HDF5。Python 端应优先使用 `h5py`，或实现以下兼容逻辑：

```text
普通 MAT 文件 → scipy.io.loadmat
MATLAB v7.3 文件 → h5py.File
```

读取 v7.3 文件时还需要统一维度方向，避免 MATLAB 与 HDF5 的数组维度顺序差异影响绘图。

### 4.5 不要在重放脚本中修正原调度模型的物理公式

当前储能放电效率的实现方式存在进一步核查空间，但本次重放的首要目标是复现已有 Pareto 解。第一阶段必须保持与原调度函数完全相同的计算逻辑。

物理公式修正应单独开分支，并在修正后重新运行优化，不应与逐小时结果导出混在同一个提交中。

## 6. 新增 `reproduce_dispatch.m`

### 6.1 功能定位

`reproduce_dispatch.m` 是逐小时调度复现入口。它负责：

1. 识别 SSP 目录；
2. 加载该目录下的 `optimization_config.m`；
3. 读取对应年份的 HDF5 Pareto 结果；
4. 自动选择 preferred solution，或使用用户指定的 Pareto 解编号；
5. 重建候选格网、装机容量和逐小时发电序列；
6. 调用重放核心执行 8760 小时调度；
7. 调用验证模块；
8. 保存结果。

### 6.2 推荐接口

```matlab
function outfile = reproduce_dispatch(year, sol_idx, scenario_dir)
% reproduce_dispatch 复现一个 Pareto 解的 8760 小时调度结果
%
% 用法：
%   addpath('..');
%   reproduce_dispatch(2050, 0, pwd);
%
% 参数：
%   year         2030 / 2040 / 2050
%   sol_idx      0 表示自动筛选 preferred solution；正整数表示指定 Pareto 解
%   scenario_dir Optimization_ssp126 / Optimization_ssp245 / Optimization_ssp560
%
% 输出：
%   results/hourly_dispatch_<year>_sol<idx>.mat
```

命令行示例：

```bash
cd Optimization_ssp126

/data6/yanxiaokai/MATLAB/R2024b/bin/matlab -batch \
  "addpath('..'); reproduce_dispatch(2050, 0, pwd);"
```

### 6.3 年份与互联模式映射

| 年份 | 结果文件 | 调度模式 | 最大路径节点数 |
|---:|---|---|---:|
| 2050 | `results/Optimization_SC_2050_Res.h5` | S-C，大陆互联 | `3` |
| 2040 | `results/Optimization_SC_2040_Res.h5` | S-C，大陆互联 | `3` |
| 2030 | `results/Optimization_SA_2030_Res.h5` | S-A，相邻互联 | `2` |

### 6.4 Preferred solution 的获取

当 `sol_idx == 0` 时，复用：

```text
utils/select_preferred_solution.m
```

根据各 SSP 自己的：

```text
BASE_LOAD_RATIO_<year>
MIN_VRE_SHARE_<year>
MAX_VRE_SHARE_<year>
MAX_CURTAILMENT
SELECTION_MODE
```

筛选 preferred solution。

当 `sol_idx > 0` 时，直接读取：

```matlab
scale = res_scale(sol_idx, :);
```

并在输出元数据中标记：

```text
selection_status = manual
```

## 8. 新增 `utils/replay_dispatch_core.m`

### 8.1 功能定位

该函数复制现有 `OptFun_*_Dispatch_*.m` 中的逐小时调度逻辑，但将中间变量完整返回。

推荐接口：

```matlab
function detail = replay_dispatch_core( ...
    all_gens, all_loads, CGrid_Index, scale, ...
    nonlsol, base_load_ratio, maxNodes)
```

### 8.2 分能源类型聚合

首先读取选址变量：

```matlab
N_grid = size(CGrid_Index, 1);
selected = round(scale(1:N_grid)) == 1;
```

构造类型掩膜：

```matlab
is_solar = false(N_grid, 1);
is_solar(1:nonlsol) = true;

is_wind = ~is_solar;
is_onshore_wind = is_wind & (CGrid_Index(:, 3) == 0);
is_offshore_wind = is_wind & (CGrid_Index(:, 3) == 1);
```

按区域聚合：

```matlab
solar_gens = zeros(20, 8760);
onshore_wind_gens = zeros(20, 8760);
offshore_wind_gens = zeros(20, 8760);

for gg_ind = 1:20
    solar_idx = ...
        CGrid_Index(:, 1) == gg_ind & selected & is_solar;

    onshore_idx = ...
        CGrid_Index(:, 1) == gg_ind & selected & is_onshore_wind;

    offshore_idx = ...
        CGrid_Index(:, 1) == gg_ind & selected & is_offshore_wind;

    solar_gens(gg_ind, :) = nansum(all_gens(solar_idx, :), 1);
    onshore_wind_gens(gg_ind, :) = nansum(all_gens(onshore_idx, :), 1);
    offshore_wind_gens(gg_ind, :) = nansum(all_gens(offshore_idx, :), 1);
end

grid_gens = solar_gens + onshore_wind_gens + offshore_wind_gens;
```

### 8.3 新增逐小时诊断数组

除原有数组外，再增加：

```matlab
storage_charge_ele = zeros(8760, 20);
storage_discharge_ele = zeros(8760, 20);

shifted_sent_ele = zeros(8760, 20, 20);
shifted_received_ele = zeros(8760, 20, 20);
transmission_loss_ele = zeros(8760, 20, 20);
```

输电时：

```matlab
sent = t_amount;
received = sent * (1 - g_costs(ad_grid_ind));

shifted_sent_ele(time_ind, gg_ind, g_route(end)) = ...
    shifted_sent_ele(time_ind, gg_ind, g_route(end)) + sent;

shifted_received_ele(time_ind, gg_ind, g_route(end)) = ...
    shifted_received_ele(time_ind, gg_ind, g_route(end)) + received;

transmission_loss_ele(time_ind, gg_ind, g_route(end)) = ...
    transmission_loss_ele(time_ind, gg_ind, g_route(end)) + sent - received;
```

储能时：

```matlab
storage_charge_ele(time_ind, gg_ind) = t_amount;
storage_discharge_ele(time_ind, gg_ind) = t_amount;
```

注意：`storage_discharge_ele` 必须沿用当前模型中 `t_amount` 的口径，不在本次修改中调整放电效率公式。

## 9. 新增 `utils/validate_hourly_dispatch.m`

### 9.1 目标函数一致性

重放结果必须与已保存 Pareto 解一致：

```matlab
replay_f1 = sum(detail.curtailed_ele(:)) ./ sum(detail.grid_gens(:));
replay_f2 = sum(detail.flexible_ele(:)) ./ sum(detail.all_loads(:));

assert(abs(replay_f1 - prs(sol_idx, 1)) < 1e-8);
assert(abs(replay_f2 - prs(sol_idx, 2)) < 1e-8);
```

建议再调用一次现有目标函数，验证三个目标：

```matlab
expected_f = OptFun_...(all_ins, all_gens, all_loads, CGrid_Index, scale, base_load_ratio);

assert(max(abs(expected_f(:)' - prs(sol_idx, :))) < 1e-8);
```

这样可以确认：

- 历史 HDF5 文件与当前代码版本一致；
- 重放脚本与原调度函数一致；
- 成本目标未发生偏移。

### 9.2 风光发电来源守恒

对每个区域、每个小时验证：

```text
风光原始出力
=
本地直接消纳
+ 跨区送出
+ 储能充电
+ 弃电
```

对应实现：

```matlab
shifted_out = squeeze(sum(detail.shifted_sent_ele, 3))';

lhs = detail.grid_gens;
rhs = detail.consumed_ele' + shifted_out + ...
      detail.storage_charge_ele' + detail.curtailed_ele';

assert(max(abs(lhs(:) - rhs(:))) < 1e-8);
```

实际实现时需统一矩阵方向，避免 `20 × 8760` 与 `8760 × 20` 混用。

### 9.3 净负荷满足守恒

对每个区域、每个小时验证：

```text
扣除基荷后的净负荷
=
本地直接消纳风光
+ 跨区受入
+ 储能放电
+ 灵活电源
```

对应实现：

```matlab
shifted_in = squeeze(sum(detail.shifted_received_ele, 2));

lhs = detail.grid_load';
rhs = detail.consumed_ele + shifted_in + ...
      detail.storage_discharge_ele + detail.flexible_ele;

assert(max(abs(lhs(:) - rhs(:))) < 1e-8);
```

### 9.4 输电损耗守恒

```text
送出电量 - 受入电量 = 输电损耗
```

### 9.5 储能 SOC 守恒

沿用当前模型口径：

```text
SOC(t+1)
=
SOC(t)
+ 充电量 × 0.95
- 放电量
```


至少包含：
